# Image upload hardening

All four admin upload endpoints use a shared raster decoder, bounded read (4 MiB), dimension limit (4096 px per edge and 16 million pixels), extension and MIME consistency check, single-frame check, full decode and fresh encoding. JPEG, PNG and WebP are supported, ICO only for favicon. SVG and animated images are not supported. JPEG uses .jpg consistently; JPEG/WebP may be recompressed. EXIF orientation is applied before metadata removal. Fresh output also has a 4 MiB limit. Resize larger images before upload. Vercel can reject oversized multipart bodies before the function runs; application limits do not replace platform request limits.

Stored filenames remain random UUIDs. New serving requests reject unknown folders, malformed IDs and non-image stored MIME types. Stored image responses get a sandbox CSP; existing immutable cache behavior is preserved. Existing files are not re-encoded by this change, and legacy /uploads assets remain unchanged. Historical images should be reviewed separately if they came from untrusted sources. No database migration or additional dependencies. Test with the isolated database and verify normal uploads/preview/favicon in production.
