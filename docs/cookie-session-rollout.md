# Staged admin cookie session rollout

Backend creates admin_sessions via existing create_all. Only SHA-256 digests of random session tokens are stored; sessions expire after one hour. Cookie is __Host-rg-session, Secure, HttpOnly, SameSite=Strict, Path=/ and no Domain. Logout deletes the session. Admin account edits/deletion revoke cookie sessions. Legacy bearer tokens remain supported until explicitly disabled. Cookie auth requires authenticated proxy and exact production Origin plus X-RG-CSRF: 1 on mutations.

Generate a fresh independent secret with python -c "import secrets; print(secrets.token_hex(32))". Set ADMIN_PROXY_SECRET to the same value in Vercel backend production and Cloudflare Pages production runtime (encrypted secret). Never prefix it with VITE_, put it in Git, paste into chat or expose it to the browser. Keep VITE_API_URL unchanged. Deploy backend then frontend; check GET https://research-guru.pages.dev/api/auth/session/me returns 401, not 403/503/HTML. Only then set VITE_COOKIE_AUTH=true in Cloudflare production build settings and redeploy. Login in a fresh browser, verify cookie flags and absence of adminToken in localStorage, reload admin, test mutation/upload, logout and replay protection using local tests. Public API calls and images continue direct to Vercel; only admin and session requests proxy. Preview hosts cannot use cookie mode. Cloudflare CF-Connecting-IP is forwarded only with shared secret; direct Vercel IP handling remains unchanged.

After successful production verification set ALLOW_LEGACY_BEARER=false in Vercel and redeploy; verify cookie login again. For rollback enable legacy bearer first, then disable VITE_COOKIE_AUTH and redeploy frontend. Do not remove shared secret while cookie mode is active. Existing legacy JWTs are not server-revocable on logout, hence disable them after verification. Do not test against production database. Local tests use isolated SQLite and mock proxy headers; real Cloudflare/Vercel deployment remains to be verified.
