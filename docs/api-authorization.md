# API authorization review

All existing /api/admin/ routes depend on get_current_admin. All active admin accounts intentionally have the same privileges; this is not a multi-tenant/customer-account system. Public blog detail, list and SEO endpoints filter unpublished articles. Public review submission forces moderation, even if a request sends administrative flags. Public files are intended for public website assets, including images attached to draft posts; they must not be used for confidential documents. Public site settings expose only configured presentation and business contact keys.

Admin JWTs now bind the username, database account ID and current password hash via a server-keyed HMAC. The password hash is not returned in the JWT. Password changes revoke old tokens; deleted or inactive accounts cannot authenticate. Existing tokens without the new claims are rejected, so admins must sign in again after deployment. No schema migration or secret rotation is needed. Logout still clears browser storage only; revocation on logout and permanent revocation on disable/reactivate require a session-version mechanism, planned with the cookie rollout.

Run backend tests on isolated SQLite (default) or dedicated test PostgreSQL only. Route-level anonymous and invalid-token tests discover all /api/admin/ endpoints. Production smoke test: sign in again and verify dashboard/admin actions. Never test destructive endpoints against production data. HTML email escaping, persistent throttling, upload content hardening and browser cookie transport are separate milestones.
