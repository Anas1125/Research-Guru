# Research Guru custom domain launch

Target canonical host: https://researchguruglobal.com. Existing host: https://research-guru.pages.dev. This PR prepares exact CORS and cookie-proxy allowlists; it intentionally leaves canonical URLs and sitemap on the existing live host until custom-domain HTTPS works. Host-only cookies do not carry across hosts; sign in again.

1. Domain owner invites the developer to their Cloudflare account with appropriate zone DNS and Pages management permissions. Create a Pages project in the domain owner's account using the existing GitHub repo (authorize GitHub access). The apex must be in the same account as the Pages project. Do not delete the current Pages project.
2. Test this branch locally before merging. Deploy backend first once Vercel quota permits. Keep the existing backend and database. Do not create a new database.
3. New Pages production build settings: branch main, root frontend, command npm run build, output dist. Copy relevant existing production settings, including VITE_API_URL=https://research-guru-nu.vercel.app, VITE_COOKIE_AUTH=true, VITE_CSP_ENFORCE=true, and the existing ADMIN_PROXY_SECRET as an encrypted runtime secret (must match Vercel; never expose in a VITE_ variable). Confirm current settings before copying.
4. Attach researchguruglobal.com in the new Pages project's Custom domains tab and wait for DNS and HTTPS activation. Preserve unrelated DNS records (including email). Use the apex for all sign-ins; www may redirect to apex after verifying DNS/TLS.
5. Verify public pages, enquiry form, admin login/logout, session-proxy /api/auth/session/me, protected writes, uploads, and security headers. Anonymous session endpoint should return 401 with a correctly configured proxy. Old origin remains usable during migration. Newly created project pages.dev preview URL is not an authorized admin host.
6. After successful verification, change SITE_URL in frontend/src/utils/seo.js and the static robots/sitemap fallback files to the new canonical host; build and test; verify dynamic sitemap, published article metadata, and robots.txt. Verify the new Search Console domain property and submit sitemap. Then redirect legacy production pages.dev and www URLs to the apex, preserving path and query; do not redirect session/API requests in use. Remove old origin from auth and CORS only after migration is complete. Keep rollback available until verified.
